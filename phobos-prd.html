1 Overview ¶

Phobos is one Rust codebase, with no C in the tree. It plays every commercial id Tech 1 IWAD from Doom to Final Doom and the free Freedoom IWADs. The engine picks its game mode from the IWAD it loads. Fidelity is the product. Vanilla demos shall play back in sync and level statistics shall match Chocolate Doom, the reference vanilla port. This keeps the port honest: a behavioural difference shows up as a failed test, not as a forum report.

The game logic is transliterated by hand from the GPL source release. The platform, I/O, audio, and presentation layers are written as idiomatic Rust from the start. A software renderer, ported from the original r_*.c, is the reference for how the game looks. A wgpu renderer with optional enhancements comes later and is checked against that reference. It never replaces it.

3 Needs ¶

Players and preservationists want to play the classic id Tech 1 games on current Linux systems with vanilla behaviour: the same physics, the same monster behaviour, the same random sequence, so that historic demos play back and speedrun records stay checkable. They supply their own IWADs and expect the engine to find them, play every map, and never crash on a malformed PWAD.

The maintainer wants a complete id Tech 1 port in safe Rust, as a showcase. The simulation shall have no unsafe, and every claim of fidelity shall be backed by a test anyone can rerun. No existing Rust effort has shipped all of Doom through Final Doom. room4doom comes closest and still lacks the cast call and the automap.

6 Principles ¶

  1. Correctness before cleverness. Where gameplay depends on a behaviour, vanilla behaviour wins, including documented bugs.
  2. Determinism is the contract. The simulation has a fixed 35 Hz tic, 16.16 fixed-point maths with explicit wrapping, the original random tables, a stable iteration order, and no wall-clock time, floating point, or renderer state.
  3. Presentation never feeds back. Renderers, audio, and UI read a snapshot of the simulation and never change it.
  4. Evidence over assertion. Each fidelity claim names the test that proves it.
  5. Untrusted by default. Every byte of a WAD, demo, or save is parsed with checked bounds into typed errors.

7.1 Porting Strategy ¶

Phobos uses manual transliteration (porting reference, strategy 3). Game-logic files (p_*, g_game, info, tables, m_random, m_fixed) keep their function boundaries and call order, so a diff against linuxdoom-1.10 stays readable and the random-number call sequence is preserved. Rendering (r_*), video (v_video), and the front end (st_*, hu_*, am_map, m_menu, wi_stuff, f_finale) keep their algorithms but use idiomatic data structures. Platform code (i_*) is rewritten from scratch.

The other two strategies were rejected:

  • A doomgeneric shim plays on day one but keeps C in the tree until the end, which NG-7 forbids.
  • c2rust output carries C’s global-pointer shape into thousands of unsafe blocks. Goal G3 would then mean refactoring the whole tree a second time.

Kreimeier’s pre-release cleanup of the source added a few bugs. Chocolate Doom documents the corrections. The port follows Chocolate Doom’s corrected behaviour and credits it in CREDITS.md (§15.3, OQ-4).

Dependency rules, enforced by cargo deny bans and checked at review:

  • phobos-sim depends only on phobos-fixed and phobos-data.
  • No renderer depends on phobos-wad. Renderers receive decoded resources.
  • Only phobos-app and phobos-gpu depend on windowing or GPU crates.

7.3 State Ownership ¶

The C engine keeps its state in mutable globals. Phobos keeps it in owned structs passed down the call tree:

  • Level owns the map geometry, sectors, lines, blockmap, and reject table.
  • World owns the Level, the thinker arena, the players, and the random indices. A tic is fn tick(&mut World, &[TicCmd; MAXPLAYERS]).
  • Thinkers live in an arena addressed by generational handles. An index-linked list inside the arena keeps the vanilla insertion and iteration order. That order decides the random-call sequence, so demo sync depends on it. Pointer fields such as mobj_t.target and tracer become Option<MobjHandle>. A handle to a removed thing resolves to None. In C, the same case reads freed memory that the zone allocator had not yet reused. The port reproduces that observable result explicitly.
  • Sector thing lists and blockmap links keep their vanilla link order, for the same reason.
  • The arithmetic overflows that vanilla relies on use wrapping_* operations explicitly. overflow-checks = true stays on in test profiles so that any accidental overflow fails.

7.4 Concurrency Model ¶

WorkModelDecision and trade-off
Simulation ticSerial, one threadDeterminism needs one exact order of random calls and thinker updates. A tic costs well under 1 ms, so by Amdahl’s law parallelism could save almost nothing and would risk desync. Serial is chosen and documented here.
Event loop and presentationwinit main threadwinit requires the main thread on several platforms. Frames go from the game thread to the presenter through a triple buffer, so neither side waits for the other.
Software rendererSerial at 320x200. Optional banded parallel drawing with Rayon at 2x and 4x scale (R-056)BSP traversal is serial by nature. Column and span drawing for screen bands can run in parallel once clipping is done. Adopted only if a benchmark shows a gain over serial at that scale.
Audio mixing and OPL synthesiscpal callback threadThe simulation sends sound commands over a bounded lock-free SPSC queue and never blocks. If the queue is full, the oldest command is dropped and counted.
Level loadRayon over texturesTexture compositing and patch decoding are embarrassingly parallel. Kept only if it beats serial on the reference machine.
Demo corpus in CIOne process per demoShared-nothing parallelism over the corpus.

7.5 Rendering ¶

Software renderer (reference, M3)

A port of r_*.c that writes palette indices to a 320x200 framebuffer (or 2x / 4x scale, optional). Colour maps, light diminishing, fuzz, sky, masked mid-textures, and sprite clipping follow vanilla. Vanilla render limits (visplanes, drawsegs, vissprites) are enforced by default and overflow into a logged, non-fatal fallback. Vanilla crashes in this case; Phobos does not. A limit-removing mode is optional (R-085).

Presenter (M3)

The indexed frame is uploaded to a wgpu texture. A small WGSL shader expands it through PLAYPAL and applies palette flashes. The output is scaled to 4:3 aspect, with integer scaling as an option. If no GPU adapter is available, a softbuffer CPU path is used.

Enhanced renderer (M8)

A wgpu renderer reads the same RenderSnapshot. It stores static level geometry in GPU buffers, draws sprites with instancing, and applies colour-map lighting in the shader. Dynamic lights, post-processing, and ray-traced effects are optional. Its output is checked against the software renderer on golden scenes.

Next: Platform and Files, Previous: Rendering, Up: Architecture   [Contents][Index]

7.6 Audio ¶

Sound effects

DMX DS* lumps are decoded and resampled to the output rate. There are 8 channels, using vanilla’s priority and channel-stealing rules, distance attenuation, and stereo separation (s_sound.c).

Music

The MUS sequencer drives an OPL3 emulator voiced from the IWAD’s GENMIDI bank, the vanilla sound. Candidate crate: nuked-opl3, a pure-Rust port. It is at 0.1.0 and needs the §24 audit before adoption. SoundFont MIDI is optional.

Degraded mode

If no audio device is available, the game runs silent and logs one warning.

7.7 Platform and Files ¶

  • Windowing and input use winit. Gamepads use gilrs (optional).
  • File locations follow XDG. Configuration goes in $XDG_CONFIG_HOME/phobos/phobos.toml; saves and demos in $XDG_DATA_HOME/phobos/.
  • IWAD search order: -iwad, DOOMWADDIR, DOOMWADPATH, the XDG data directories plus doom/, then the current directory.
  • No network access in any build (§9).
  • The engine uses no fonts of its own except on the no-IWAD screen and the debug overlay. Those use bundled Share Tech Mono / Inconsolata (OFL, §12) and the steelbore theme (§11, §11.6). In-game menus and HUD use IWAD graphics.

12 Risks ¶

RiskImpactLikelihoodMitigation
Demo desync from subtle order or overflow differencesHighHighPer-tic checksums, Chocolate Doom oracle, demo diff first-divergence tool, transliteration that keeps call order.
Thinker or link order lost when pointers become handlesHighMediumIndex-linked lists in the arena; golden traces on monster-heavy maps.
Vanilla undefined behaviour (freed target, overflows) is relied on by demosMediumMediumEmulate the observable result explicitly; R-040 optional overflow emulation.
Commercial IWADs absent from CIMediumCertainFreedoom and shareware in CI; a scripted local acceptance run before each release.
Young OPL crateMediumMedium§24 audit; fallback is porting Nuked OPL3 in tree, keeping its LGPL-2.1-or-later notice (§4.2).
wgpu API churnLowHighPresenter stays thin; softbuffer fallback; versions pinned.
Scope creep toward Boom or ZDoomHighHighNG-1; DeHackEd is the only extension format.
Trademark complaintMediumLowCodename, no assets, no logos, disclaimer.
